## T9 OpenF1 수집

- 작업일: 2026-11-11
- 결과: 2023–2025년 그랑프리 본 예선과 결승 140개 세션의 drivers, laps, stints, pit, weather, race_control, session_result를 `data/curated/openf1/`에 실었다(랩 99,523행). 미팅 대응표(`meeting_map.csv`, 70행)와 드라이버 대응표(`driver_map.csv`, 69행)를 만들었다.

  - 날씨 결측 규칙: 노면 온도, 습도, 기압이 0 이하면 결측으로 바꾼다. 이번 범위에는 해당 값이 없었다(노면 온도 12.0–54.6도).

  - 드라이버 대응: 차량 번호로 맞춘 68건은 양쪽 약칭이 모두 같다. 1건(2023년 싱가포르의 Stroll)은 결승에 나오지 않아 OpenF1 결승 세션에 없다.
- 완료 기준에 못 미친 부분: 대응표를 사람이 검수하는 단계가 남았다. 자동 대조(약칭 일치)만 했다.
- 메모: 스프린트 예선과 스프린트는 받지 않았다. 지수 계산에 쓰지 않기 때문이다.

## T10 페이스 지수

- 작업일: 2026-11-11
- 결과: `data/curated/pace/qualifying_index.parquet`(1996–2025년 568개 대회, 5,991행), `race_index.parquet`(2023–2025년 70개 대회, 700행).

- 사용자 결정 대기: 지표 정의 승인, 2022년 이전 우천 플래그 방법.

## T13 자동 갱신 워크플로 (수동 재현)

- 작업일: 2026-11-11
- 결과: 깨끗한 작업 트리에서 2025년 24라운드(아부다비)를 `post-session`, `post-race`로 다시 돌렸다. 처음에는 내용이 같은데 Parquet 파일이 다시 써졌고, API에 없는 덤프 값(결과 상태 코드 20행, 기록 없는 Q3 드라이버의 세션 순위 1행)이 비었다. 기존 값을 두고 내용이 같으면 파일을 쓰지 않도록 고친 뒤에는 정제 테이블이 바뀌지 않고 `datasets.csv`의 OpenF1 수집 시각만 바뀐다. 이 동작은 `test_replaying_a_dump_round_changes_nothing`이 검사한다.
- `fia-weekend`도 같은 대회로 재현했다(T6 커밋 뒤). 새 문서 0건, 정제 테이블 변화 0건이다.
- GitHub Actions 수동 트리거(2026-11-11): `post-race` 2025년 24라운드. 첫 실행은 갱신 뒤 테스트 하나가 실패했고, 실패 이슈(#1)가 자동으로 생겼다. 테스트를 고친 뒤 다시 실행해 성공했다(run 42981701484). 갱신, 테스트, 커밋, 사이트 재배포까지 이어졌고, 커밋된 변경은 `datasets.csv`의 API 반영 행 하나다. 정제 테이블은 바뀌지 않았다.
- 스케줄을 켜기 전에 고칠 점: `fia-weekend`는 `pu_elements.build()`와 `car_presentation.build()`로 모든 시즌을 다시 만든다. 그런데 러너의 원문 캐시(`actions/cache`, 키 `raw-`)는 CI 테스트 표본만 담고 있어서, 첫 실행에서 PU 문서 297건과 Car Presentation 54건을 fia.com에서 다시 받게 된다(시간당 80건 한도로 4시간 이상). 그 대회 문서만 받아 기존 정제 테이블에 더하는 증분 빌드나, 원문 캐시를 한 번 채워 두는 별도 작업이 필요하다. 그래서 Actions 수동 재현은 `post-race`, `post-session`만 한다.
